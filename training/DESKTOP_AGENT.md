# 台式机 Claude Code 任务书

把下面「任务简报」整段粘给台式机上的 Claude Code。先读这一页，它解释了为什么简报是这样写的。

---

## 什么适合交给 agent，什么不适合

| 环节 | 交给 agent？ | 原因 |
|---|---|---|
| 自动搜索/抓取语料 | **不要** | 通用语料对 Qwen3-4B 无增益甚至有害；还有授权问题 |
| 语料清洗、去重、统计 | 适合 | 机械活，规则明确 |
| 抽检教师输出质量 | 适合 | 有明确的判废标准 |
| 盯 loss、发现发散/NaN | 很适合 | 人盯几小时不现实 |
| OOM 后调小 batch 重试 | 很适合 | 机械恢复 |
| 导出 + 跑评测 + 对比基线 | 很适合 | 有硬性验收门槛 |
| **判定"训练成功"** | **不要** | 必须由评测数字决定，不能由 agent 自我宣布 |

核心原则：**agent 负责执行和监控，验收由数字说了算。**

## 为什么不让它自动找语料

1. **通用英文没有增益。** Qwen3-4B 已经见过互联网。拿泛语料微调，好的情况是没变化，
   坏的情况是灾难性遗忘。蒸馏的价值 100% 来自领域匹配。
2. **分布必须匹配生产输入。** 学生上线后收到的是 Whisper 的输出——带识别错误、
   口语停顿、断句瑕疵。拿干净书面英文训练等于训了一个用不上的条件分布。
   所以英文侧应当由 `0_prepare_corpus.py` 转录真实音频生成。
3. **授权。** 抓来的文本用于训练涉及版权，这个判断得你来做，不该由 agent 代劳。

## /goal 模式适合吗

适合**监督**，不适合**长时间轮询**。

QLoRA 跑 1~3 小时，如果让 agent 每分钟检查一次，几小时下来纯浪费 token 而且什么也没做。
正确姿势：

- 训练用 `run_in_background` 起，让它在后台跑，完成时自动通知
- `/goal` 的条件写成**可验证的终态**（见下方简报），而不是「盯着训练」
- 需要周期性检查时，间隔设成 15~30 分钟，不要 1 分钟

## 任务简报（复制下面全部内容）

```
目标：在这台 4090 上，用 Qwen3-14B 作教师，蒸馏出一个微调过的 Qwen3-4B，
并导出成 OpenVINO INT4 格式，供另一台笔记本上的同声传译软件使用。

项目代码在 <你把仓库放的路径>，训练脚本在 training/，先读 training/README.md。

【已经确定的，不要改】
- 教师 Qwen/Qwen3-14B，学生 Qwen/Qwen3-4B
- 训练脚本必须从 app/mt.py import SYSTEM_PROMPT 和 NO_THINK，不要复制粘贴提示词。
  训练和推理的提示词差一个字，微调就白做。
- loss 只算在中文补全上，不算在提示词上（2_train_lora.py 已实现，别动）
- 导出必须是 INT4 group_size=128 ratio=1.0，与基线模型的量化方式一致，否则没法比较

【语料】
- 英文侧由我提供，放在 corpus.txt，一行一句。
  它是用 Whisper 转录真实音频得到的，**带有识别错误和口语瑕疵，这是故意的**，
  不要"清洗"掉这些噪声，那是学生在生产环境真实会遇到的输入。
- 你可以做：去重、去掉长度异常的行、统计词频和长度分布、报告可疑样本
- 你不要做：自己去网上搜集语料、替换成"更干净"的文本

【执行步骤】
1. 检查环境：CUDA 可用、显存 24GB、依赖齐全（见 training/README.md）
2. 跑 1_generate.py 生成 train.jsonl
   - 完成后随机抽 30 条给我看，我要确认教师翻译质量
   - 报告 rejected 统计，如果废弃率超过 15%，停下来告诉我原因
3. 跑 2_train_lora.py
   - 后台运行，不要每分钟轮询
   - 关注：loss 是否下降、有没有 NaN、验证集 loss 是否开始上升（过拟合）
   - OOM 就把 --batch 减半、--accum 加倍后重试，并告诉我
4. 跑 3_export_openvino.py 导出 INT4
5. 报告最终文件夹大小和路径

【验收门槛 —— 这是唯一的成功标准】
不要凭 loss 曲线宣布成功。必须把导出的模型拷到笔记本，跑：
    python tools/eval_translation.py --models <基线模型> <新模型>
对比 eval_baseline.json（基线：12/12 通过，1230 ms/句）。

只有满足全部三条才算成功：
  a) 自动检查通过数 >= 12/12（不能有回归）
  b) 并排译文经我人工确认质量不低于基线
  c) 平均耗时不显著变差（<1400 ms/句）

如果导出后评测变差，先用 --int8 重新导出再测一次 —— 有可能是 INT4 量化
吃掉了微调增益，而不是训练本身失败。这两种情况的处理方式完全不同。

【不要做的事】
- 不要自动收集或下载语料
- 不要在我没看过抽检样本前就开始训练
- 不要因为 loss 好看就说"训练成功"
- 不要删除 eval_baseline.json 或改动 tools/eval_translation.py 的测试集
  （改了测试集，前后就没法比了）
- 每次导出覆盖同名目录，不要留 v1/v2/v3 一堆副本占硬盘
```

## 你需要亲自做的三个判断

1. **语料选哪些音频。** 越贴近你实际使用场景越好（你的课程录像、行业讲座、
   会议录音）。授权问题你自己把关。
2. **抽检教师输出。** agent 会给你 30 条，你扫一遍。如果 14B 翻得也一般，
   整个蒸馏就没意义，及早止损。
3. **最终质量判定。** 自动检查只是回归网。并排译文得你来读——我们已经吃过一次亏：
   两个模型都把 "quarter over quarter" 译成「同比」，自动检查全部通过。
